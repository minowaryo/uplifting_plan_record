### UC-001: ログインする

**Actor**: 全Actor
**前提条件**: 有効なアカウントが作成済み
**関連要件**: F-001

#### 基本フロー
1. Actor がログイン画面でメールアドレス/パスワードを入力する
2. システムが認証情報を検証する
3. システムがマイページへ遷移させる

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| email | string | 必須 | email形式, 最大255文字 |
| password | string | 必須 | 8文字以上 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| auth_user | object | 認証済みユーザー情報 |
| redirect_to | string | 遷移先URL（マイページ） |

#### 業務ルール
- 5回連続失敗で一時ロックする（ロック時間は運用設定値）
- 非アクティブユーザーはログイン不可

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 認証情報が不正 | 401 | ログイン情報が正しくありません |
| 無効化ユーザー | 403 | このアカウントは利用できません |

#### 権限
- 未認証ユーザー: 実行可
- 認証済みユーザー: ログイン画面へは遷移不可（マイページへリダイレクト）

### UC-002: マイページでメンター/メンティ情報を確認する

**Actor**: 全Actor（認証済み）
**前提条件**: ログイン済み
**関連要件**: F-002

#### 基本フロー
1. Actor がマイページを開く
2. システムがメンター/メンティ関係、直近プラン、未入力警告を集約して表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| なし | - | - | - |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| mentor_relations | array | 自分がメンティとして持つ関係 |
| mentee_relations | array | 自分がメンターとして持つ関係 |
| plan_summaries | array | トレーニング/メンタリング計画の概要 |
| warnings | array | 未入力警告などの注意情報 |

#### 業務ルール
- メンターとメンティは同一ユーザーが同時に持ち得る
- 権限外の他者詳細情報は表示しない

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 未認証アクセス | 401 | ログインしてください |

#### 権限
- 認証済みユーザー: 実行可

### UC-003: スキル評価を登録・更新する

**Actor**: チームヘッド（主担当）、セクションヘッド、管理者
**前提条件**: 対象ユーザーが所属しているチーム/セクションが設定済み
**関連要件**: F-004

#### 基本フロー
1. Actor が対象メンバーを選択する
2. システムが対象セクションに有効なスキル項目のみ表示する
3. Actor が各スキルを1〜4で入力し保存する
4. システムが履歴を保存し最新評価を更新する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| user_id | integer | 必須 | 存在するユーザーID |
| skill_id | integer | 必須 | セクション有効スキルのみ |
| level | integer | 必須 | 1〜4 |
| comment | string | 任意 | 最大1000文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| saved_count | integer | 保存件数 |
| updated_at | datetime | 更新日時 |

#### 業務ルール
- チームヘッドは自チーム所属メンバーのみ更新可
- セクションヘッドは配下チームのメンバーを更新可
- 管理者は全ユーザー更新可

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 権限外ユーザーの更新 | 403 | このユーザーの更新権限がありません |
| レベルが範囲外 | 422 | レベルは1〜4で入力してください |

#### 権限
- チームヘッド/セクションヘッド/管理者: 実行可
- 一般ユーザー: 実行不可（403）

---

### UC-004: スキル項目を管理しセクションに割り当てる

**Actor**: セクションヘッド、管理者
**前提条件**: スキルマスタ管理画面にアクセスできる
**関連要件**: F-004a, F-004b

#### 基本フロー
1. Actor がスキル項目を追加/廃止する
2. Actor がセクションごとに利用スキルをオン/オフ設定する
3. システムがセクション別スキルセットを更新する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| skill_name | string | 必須 | 1〜100文字, 重複不可 |
| section_id | integer | 必須 | 存在するセクションID |
| enabled | boolean | 必須 | true/false |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| skill_master | array | 現在のスキル項目一覧 |
| section_skill_set | array | セクション別有効スキル |

#### 業務ルール
- スキル項目は共通マスタとして管理する
- セクションごとに必要なスキルだけを有効化できる
- セクションで有効でないスキルは評価入力対象に出さない

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 重複スキル名 | 422 | 同名のスキル項目が既に存在します |
| 権限なし | 403 | スキルマスタ管理権限がありません |

#### 権限
- セクションヘッド/管理者: 実行可
- チームヘッド/一般ユーザー: 実行不可（403）

### UC-005: スキル未入力警告を表示する

**Actor**: チームヘッド、セクションヘッド、管理者
**前提条件**: 表示対象期間が確定している
**関連要件**: F-005a

#### 基本フロー
1. Actor がダッシュボードを開く
2. システムが未入力スキルを都度検知する
3. システムが画面上に警告を表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| section_id | integer | 任意 | 権限範囲内 |
| team_id | integer | 任意 | 権限範囲内 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| warning_count | integer | 未入力警告件数 |
| warning_members | array | 未入力メンバー一覧 |

#### 業務ルール
- 通知は外部送信せず画面内警告のみ
- 検知タイミングは画面表示時（都度判定）

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 権限外の組織指定 | 403 | 指定組織の参照権限がありません |

#### 権限
- チームヘッド/セクションヘッド/管理者: 実行可

### UC-006: トレーニングプランを管理する

**Actor**: チームヘッド、セクションヘッド、管理者
**前提条件**: セクション・チームが設定済み
**関連要件**: F-006

#### 基本フロー
1. Actor が対象セクションを選択する
2. Actor が期間・目標・対象メンバーを設定して保存する
3. システムがプランを公開し一覧に反映する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| section_id | integer | 必須 | 存在するセクションID |
| title | string | 必須 | 1〜200文字 |
| start_date | date | 必須 | 終了日以前 |
| end_date | date | 必須 | 開始日以降 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| training_plan_id | integer | 作成/更新されたプランID |
| status | string | draft/published |

#### 業務ルール
- チームヘッドは自チーム配下の計画のみ編集可
- セクションヘッドは配下チーム分を統括可能

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 日付不整合 | 422 | 期間指定が不正です |
| 権限なし | 403 | プラン管理権限がありません |

#### 権限
- チームヘッド/セクションヘッド/管理者: 実行可
- 一般ユーザー: 参照のみ

### UC-007: メンタリングプランを週次で管理する

**Actor**: メンター、チームヘッド、セクションヘッド、管理者
**前提条件**: メンター・メンティのペアが設定済み
**関連要件**: F-007

#### 基本フロー
1. Actor がペアと対象週を選択する
2. Actor が翌週分テーマと達成目標を登録する
3. システムが金曜締めルールを満たしているか検証し保存する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| mentor_id | integer | 必須 | 存在するユーザーID |
| mentee_id | integer | 必須 | 存在するユーザーID |
| target_week | date | 必須 | 週開始日 |
| theme | string | 必須 | 1〜300文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| mentoring_plan_id | integer | 保存したプランID |
| deadline_status | string | on_time/late |

#### 業務ルール
- 毎週金曜日までに翌週分を登録済みにする
- 期限超過の場合は遅延ステータスを記録する

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| ペア不整合 | 422 | メンター/メンティの組み合わせが不正です |
| 権限なし | 403 | このペアのプラン編集権限がありません |

#### 権限
- メンター/管理系ロール: 実行可（権限範囲内）

### UC-008: メンタリングフィードバックを登録する

**Actor**: メンター、メンティ
**前提条件**: 対象週のメンタリングプランが存在する
**関連要件**: F-008

#### 基本フロー
1. Actor が対象プランを選択する
2. Actor がフィードバック内容を入力し保存する
3. システムが相手側からの入力有無を更新する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| mentoring_plan_id | integer | 必須 | 存在するID |
| from_role | enum | 必須 | mentor/mentee |
| comment | string | 必須 | 1〜2000文字 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| feedback_id | integer | 登録フィードバックID |
| submitted_at | datetime | 登録日時 |

#### 業務ルール
- メンターとメンティは双方が独立して投稿できる
- 1週内での再編集可否は別途運用ルールで定義

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 対象プランなし | 404 | 対象プランが見つかりません |
| 当事者以外の投稿 | 403 | このプランへの投稿権限がありません |

#### 権限
- 対象ペアのメンター/メンティ: 実行可
- それ以外: 実行不可（403）

### UC-009: フィードバック履歴を参照する

**Actor**: メンター、メンティ、チームヘッド、セクションヘッド、管理者
**前提条件**: フィードバックが登録済み
**関連要件**: F-009

#### 基本フロー
1. Actor が検索条件（期間/ユーザー/組織）を指定する
2. システムが権限範囲内データを抽出する
3. システムが一覧と詳細を表示する

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| from_date | date | 任意 | 日付形式 |
| to_date | date | 任意 | from_date以降 |
| user_id | integer | 任意 | 権限範囲内 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| feedback_list | array | フィードバック一覧 |
| total_count | integer | 件数 |

#### 業務ルール
- 当事者は自分の履歴を参照可能
- 上長は配下組織の履歴を参照可能

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| 権限外データ参照 | 403 | 参照権限がありません |

#### 権限
- メンター/メンティ/チームヘッド/セクションヘッド/管理者: 実行可（範囲内）

### UC-010: 既存Excelデータを初期移行する

**Actor**: 管理者
**前提条件**: 移行用Excelフォーマットが確定済み
**関連要件**: 制約・前提（既存Excel初期移行）

#### 基本フロー
1. 管理者がExcelファイルをアップロードする
2. システムがフォーマット検証と整合性チェックを行う
3. システムが移行対象データを登録する
4. システムが移行結果（成功/失敗件数）を返す

#### 入力
| 項目 | 型 | 必須 | バリデーション |
|---|---|---|---|
| upload_file | file | 必須 | xlsx/csv, 最大サイズ制限 |

#### 出力
| 項目 | 型 | 説明 |
|---|---|---|
| imported_count | integer | 取込成功件数 |
| error_count | integer | 取込失敗件数 |
| error_rows | array | 失敗行と理由 |

#### 業務ルール
- 本番移行前に検証環境で試験取込を必須とする
- 取込時の監査ログを保存する

#### エラーケース
| ケース | HTTPステータス | メッセージ |
|---|---|---|
| フォーマット不一致 | 422 | ファイル形式または項目定義が不正です |
| 必須列欠落 | 422 | 必須項目が不足しています |

#### 権限
- 管理者: 実行可
- その他: 実行不可（403）
